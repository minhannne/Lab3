# Decomposition — Interactive Scientist & Pioneer Directory

## 1. Goal

Transform the assignment's static dataset into an interactive React
directory containing seven people, including An, age 20, IQ 180.

Implement search, numeric filtering, sorting, deletion, restoration,
and accessible result announcements.

## 2. Component and File Responsibilities

| File | Responsibility |
| --- | --- |
| `src/data/smartPeople.js` | Export the seven-person initial dataset with stable IDs. |
| `src/components/ScientistDirectory.jsx` | Manage independent state, derive results, render controls and cards, and handle deletion and reset. |
| `src/App.jsx` | Compose the page header and directory. |
| `src/App.css` | Style the page, cards, filters, actions, and responsive layouts. |
| `src/index.css` | Define global styles, typography, and focus indicators. |
| `src/main.jsx` | Mount the React application. |

## 3. Task 1 — Normalize the Dataset

### Input

The six people supplied in the assignment and the additional person An.

### Implementation

- Create the `SMART_PEOPLE` array.
- Give each person an `id`, `name`, `age`, and `iq`.
- Use unique IDs from `sp-1` to `sp-7`.
- Store ages and IQ values as numbers.
- Render each card with `key={person.id}`.

### Expected Result

The directory displays seven people with stable identities.

### Commit

`feat(ex2): normalize smartPeople schema with stable IDs`

## 4. Task 2 — Add Search, Filtering, and Sorting

### Independent State

| State | Initial value | Purpose |
| --- | --- | --- |
| `people` | `initialData` | Current people, including deletion changes. |
| `query` | `''` | Name search input. |
| `minIq` | `160` | Numeric IQ threshold. |
| `sortBy` | `'iq-desc'` | Selected sorting mode. |

### Derived Pipeline

1. Trim the query and compare names without case sensitivity.
2. Keep people whose IQ is greater than or equal to `minIq`.
3. Sort the filtered results using `toSorted()`.
4. Render the resulting `visiblePeople` array.

Use IQ descending or age ascending according to `sortBy`.

Calculate the visible list during rendering. Do not store it in
state or synchronize it with `useEffect`.

### Input Handling

- Read numeric input using `valueAsNumber`.
- Convert `NaN` to `0`.
- Associate each control with a label using IDs generated by `useId()`.
- Prevent form submission from reloading the page.

### Expected Result

Search, filtering, and sorting work together without mutating
the original dataset.

### Commit

`feat(ex2): add search, IQ filter & toSorted`

## 5. Task 3 — Add Delete, Reset, and Live Status

### Delete

- Receive the selected person's ID.
- Use a functional state update.
- Create the new array with `filter()`.
- Preserve the IDs of all remaining people.

### Focus Management

Use refs to access the list and Reset button.

When the focused Delete button is removed:

1. Focus the next person's Delete button if available.
2. Otherwise, focus the previous person's Delete button.
3. If neither exists, focus Reset.

If another element already has focus, leave that focus unchanged.

### Reset

- Restore people from the initial dataset.
- Clear the search query.
- Restore minimum IQ to 160.
- Restore IQ-descending sorting.

### Live Status

Calculate the count from `visiblePeople.length`.

Display it in an `output` element with:

- `role="status"`
- `aria-live="polite"`

Show an empty-state message when the visible list is empty.

### Expected Result

Deletion, restoration, result counts, and keyboard focus remain
consistent with the current directory state.

### Commit

`feat(ex2): add delete/reset & live status`

## 6. Data Flow

User input or action updates independent state.

React renders the component again and calculates the visible list
from the current people, query, IQ threshold, and sorting mode.

The cards, empty state, and result count all use this same derived list.

No effect is needed to calculate or synchronize these results.

## 8. Scope

This exercise uses local React state.

storage are outside the assignment scope. Reloading the application
